# Output Presentation Spec

这个文件约束两类交付：

1. **Excel 数据源.xlsx** 的中文 Sheet 命名
2. **HTML 可视化看板** 的详细模块结构

## 一、Excel 中文 Sheet 命名规范

原则：
- 所有 Sheet 名必须为中文
- 名称应让运营、产品、老板一眼看懂，不使用英文缩写式内部名
- MD 报告里出现的关键表 / 关键结论，必须在 Excel 中能找到对应中文 Sheet

## 最小 Sheet 清单

| 英文思维中的内容 | Excel Sheet 中文名 | 用途 |
|---|---|---|
| Summary | 总览 | 研究对象、方法、结论、限制 |
| Market Overview | 市场大盘 | 大盘指标、集中度、价格结构 |
| Keyword Summary | 关键词总表 | 核心词、功能词、场景词、替代词 |
| Keyword Trend | 关键词趋势 | 月度趋势、季节性 |
| Keyword Extends | 关键词延伸词 | 延伸词与相关词 |
| Top100 Full | 类目Top100明细 | 完整 100 条数据 |
| Top100 Attr Summary | Top100属性切片 | 属性标签占位、销量结构 |
| Competitor Logic | 竞品选择逻辑 | ASIN、理由、竞品类型、覆盖维度 |
| Selected Products | 竞品基础信息 | 价格、评论、月销、卖点 |
| Review Negative Raw | 差评原始样本 | 原始负评样本 |
| Painpoint Mapping | 差评痛点归因 | 痛点、样本数、品牌能力、产品方案 |
| Traffic Terms | 流量词 | 竞品流量词、曝光词 |
| Community Signals | 社区信号 | Reddit / Quora / 论坛讨论 |
| Opportunity Ranking | 机会排序 | 三维评分、优先级 |
| Tier1 Spec | Tier1产品规格 | 完整规格建议 |
| Self Check | 交付自检 | Step 5 自检清单 |

## 命名细则

- 推荐使用：`总览`、`市场大盘`、`关键词总表` 这种简洁命名
- 不推荐使用：`summary_final_v2`、`dashboard_data`、`Top100_Full`
- 如果 Sheet 过多，可加前缀帮助排序：
  - `01_总览`
  - `02_市场大盘`
  - `03_关键词总表`
- 但前缀后的主体名仍然必须是中文

## 二、HTML 可视化看板规范

原则：
- 文件名可以叫“精简汇报.html”，但内容必须是**详细版内部决策看板**
- 风格上可以参考高管汇报型 dashboard，但信息密度必须更高
- 默认面向：操盘手、产品经理、老板、跨部门评审会
- **视觉基底应参考 2026-04-21 壁灯项目的 HTML 风格**，即暖色高密度管理层 dashboard 风格
- **但不得直接照搬壁灯版 HTML 作为最终模板**，因为那份页面只能算“第一版样式参考”，在模块深度、表格密度、决策信息完整性上仍不够
- 当前正式模板应以 `references/html_dashboard_template.html` 为准，它是在壁灯版基础上做了更深一层补强后的标准模板

## HTML 最小模块结构（至少 8 个模块）

推荐模块标题风格：
- `市场调研可视化看板`
- `市场大盘`
- `关键词透镜`
- `Top100 属性切片`
- `Gap Finder / 供需缺口`
- `竞品与 VOC`
- `决策建议`

### 推荐模板使用方式

执行时建议顺序：

1. 先读取 `references/html_dashboard_template.html`
2. 再把具体项目数据映射进去
3. 最后按项目实际情况补足更深层内容，而不是只替换标题和数字

**硬性要求：**
- 壁灯版 HTML 只能作为**视觉参考样式**，不能直接作为“交付模板”机械复用
- 正式交付必须比壁灯版更详细，尤其要加强：
  - 市场集中度拆解
  - 属性切片的交叉维度
  - Gap Finder 的原因分析
  - VOC 的 `痛点 → 品牌能力 → 产品方案` 映射
  - 决策建议中的 Tier 1 产品规格卡
  - 数据来源与限制说明

### 1. 首页概览

必须包含：
- 页面标题
- 研究对象 / 站点 / 时间 / 方法
- Go / No-Go 或机会评分卡
- 3-5 条 Executive Summary
- 6-10 个核心 KPI 卡

建议 KPI：
- 核心词月搜索量
- 红光组合词月搜索量
- Top100 月销量
- Top100 月销额
- 建议价格带
- 负评样本数
- 竞品数
- 推荐机会方向

### 2. 市场大盘

必须包含：
- 头部品牌 / 卖家集中度
- 价格带分布
- Top100 销量 vs 评论 / 星级关系
- 低评论快跑样本或新品切入难度判断

输出形式建议：
- 横向条形图
- 散点图 / 气泡图
- 结构表格
- 模块底部“当前切口建议”提示框

### 3. 关键词透镜

必须包含：
- 核心词 / 功能词 / 场景词 / 替代词对比
- 搜索量、CPC、竞品数联动展示
- 关键词明细表

输出形式建议：
- 气泡图：月搜 × CPC × 竞品数
- 关键词表格
- 关键词分层标签

### 4. Top100 属性切片

必须包含：
- Step 1.5 属性标注结果
- 至少一个属性维度切片（如功能、价格带、结构、场景）
- 支持按“月销量 / 产品数 / 月销额”切换

输出形式建议：
- 分段条形图
- 卡片汇总
- 当前切口建议框

### 5. 供需缺口 / Gap Finder

必须包含：
- 至少一个二维交叉矩阵
- 右侧机会空白 Top 列表
- 每个机会点都要写“为什么是空白 / 薄供给”

可用组合示例：
- 功能 × 价格带
- 红光 × 续航
- 热疗面积 × 价格带
- 使用场景 × 结构类型

### 6. 竞品与 VOC

必须包含：
- 代表竞品定位图
- 差评痛点强度条
- 竞品清单表
- 必要时可加供应链 / 成本带参考区块

重点：
- 差评必须按属性维度，不按单品零散罗列
- 需要体现 `痛点 → 品牌能力 → 产品方案` 映射

### 7. 决策建议

必须包含：
- Go / No-Go 评分拆解
- Tier 1 / Tier 2 / 暂缓 的机会优先级
- Tier 1 产品完整规格卡
- 为什么不建议做某些方向
- 至少 1 个明确的“不建议做”方向及原因，防止页面只会喊 Go

### 8. 数据来源与时效说明

必须包含：
- 数据采集时间
- 调用过的 MCP / Web 数据源
- 数据限制和解释口径
- 当前结论适用边界

---

## 三、每个模块的展示要求

每个 HTML 模块都必须同时具备：

1. **图表**
2. **表格或明细区**
3. **结论说明 / 洞察框**

禁止：
- 只有图，没有解释
- 只有几张卡片，没有结构化分析
- 只有表格堆砌，没有结论
- 直接复用旧项目 HTML 后只改标题、少量数字和方向名
- 把壁灯版 HTML 当成最终模板而不做深度扩写

## 四、视觉与实现要求

- 界面语言默认中文
- 风格建议：高密度、干净、偏管理层 dashboard，而不是花哨营销页
- 优先单文件 HTML
- 若拆 CSS / JS / 图片资源，统一放到相对路径 assets 下
- 禁止依赖外部 CDN 才能正常打开
- 图表可用原生 SVG / Canvas / 本地 JS 实现，重点是**离线可打开**

## 五、建议的页面节奏

推荐从上到下：

1. 先给结论和总览
2. 再给市场结构
3. 再给关键词和属性切片
4. 再给 gap 和竞品差评
5. 最后收束到决策建议

也就是说，HTML 不是“把 Excel 搬上网页”，而是：

**把研究结论压缩成一套能用于内部判断和沟通的经营视图。**

补充要求：
- 如果新的 HTML 看起来和壁灯版几乎一模一样，只是换了类目名和数字，视为不合格
- 合格的模板复用，必须体现“同一视觉语言，不同项目内容深度重新组织”
- 默认以 `references/html_dashboard_template.html` 为模板骨架，再根据项目补强，不允许回退成浅层摘要页
