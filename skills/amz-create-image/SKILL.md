# amz-create-image

## 定位

`amz-create-image` 是一个面向 Amazon 运营的视觉需求稿 Skill。它不直接产出图片成品，而是把运营判断转化为美工可执行的 Excel 需求稿。

最终需求稿必须解决：

- 产品定位是否清楚
- 主图是否有点击力
- 副图是否能解释卖点和降低疑虑
- A+ 是否能承接品牌信任和深层说服
- 竞品参考图是否直接嵌入
- 图片文案是否适合实际版式，而不是整段堆字
- 运营判断是否已经转化为图片策略，而不是只整理素材
- 图片是否同时承接关键词搜索、场景意图和 AI 导购问答

---

## 运营与算法能力定义

本 Skill 必须具备 Amazon 运营视角，不能只按参考图改版式。每次生成需求稿前，先把运营判断转化为图片策略。

### Amazon 运营能力

- **选品与定位能力**：判断产品适合谁、解决什么问题、价格带和竞品差异在哪里。
- **关键词与搜索意图能力**：区分核心品类词、长尾场景词、功能词、品牌/竞品词、问题型词，并映射到主图、副图和 A+模块。
- **Listing 转化能力**：让图片回答用户点击前和点击后的关键问题，包括规格、材质、安装、使用场景、兼容性、套装数量、售后疑虑。
- **广告与自然流量协同能力**：根据广告词、自然收录词、Search Term Report、SQP/ABA 等数据，判断哪些词需要图片承接。
- **Review/VOC 洞察能力**：把好评动机、差评痛点、退货原因和 Q&A 疑虑转成图片模块，不只摘录评论。
- **竞品拆解能力**：拆竞品的信息层级、卖点顺序、视觉钩子和未满足痛点，但不得照抄素材、参数、文案或版式。
- **供应链与利润意识**：图片策略不得制造超出真实供货、配件、认证、功能、续航、材质的承诺。
- **合规风控能力**：识别侵权、虚假参数、认证宣称、医疗/安全承诺、极限词、操纵评论等风险。

### A9 / COSMO / Rufus 理解

- **A9**：在本 Skill 中作为 Amazon 搜索排序逻辑的卖家侧简称处理。图片需求稿要服务于相关性、点击率、转化率、销量表现、价格/配送/评价/库存等综合表现，但不得声称掌握 Amazon 未公开排序公式。
- **COSMO**：按 Amazon Science 公开方向理解为电商常识知识和用户意图理解系统。图片需求稿必须表达产品适用人群、使用场景、解决的问题、搭配关系、购买理由，而不是只堆关键词。
- **Rufus**：按 Amazon 公开的生成式购物助手理解。图片和文案必须能回答对话式购物问题，例如“适合谁”“和普通款有什么区别”“是否好安装”“差评担心点是什么”“买它需要注意什么”。

### 与图片需求稿的映射

- 主图：优先承接搜索结果点击、品类识别、套装数量、核心差异和价格带感知。
- 副图：逐张回答功能、参数、安装、场景、对比、痛点、信任和购买疑虑。
- A+：承接品牌信任、深层场景、产品体系、使用教育、对比表和售后/包装说明。
- 文案：既要有关键词可读性，也要符合 COSMO/Rufus 的自然语言意图表达。
- 参考文件：`references/amazon_operation_capabilities.md`

## v7 硬性流程：分阶段交付

本 Skill 必须按阶段执行，不能一次性把主图、辅图和 A+ 全部混在一起做完。

### 阶段状态硬门禁

- 产品资料不足：只输出资料缺口清单，不生成图片需求稿。
- 未上传主图/副图参考图：只要求补充主图/副图参考图，不生成主图/副图需求稿。
- 主图/副图未验收通过：不得要求 A+ 参考图，不得生成 A+需求稿。
- 未上传 A+参考图或 A+参考图不足：只要求补充 A+参考图，不生成完整 A+需求稿。
- 参考图类型不匹配：不得借用其他阶段图片，必须要求用户补充对应阶段参考图。
- 进入 A+阶段后，必须基于主图/副图阶段已验收的原 Excel 工作簿继续补充 A+ 信息，并另存为新版本；不得从空模板新建一份只包含 A+内容的工作簿。

### Phase 0：产品资料收集

先收集：

- 产品名称、型号、站点、类目
- 售价/价格带
- 套装数量
- 核心卖点
- 产品尺寸、材质、包装清单
- 安装方式、禁用表达
- 关键词、广告词、自然收录词
- 关键词意图分类：核心品类词、功能词、场景词、痛点词、问题型词
- Review/VOC、差评痛点
- 竞品 ASIN
- A9 相关运营信号：点击、转化、价格、评价、库存、配送、Featured Offer、账户健康
- COSMO/Rufus 相关意图：适用人群、使用场景、购买任务、搭配关系、疑虑问答

资料不足时，输出缺口清单。不得虚构参数。

### 单位换算硬性规则

面向美国站图片需求稿时，用户给到的尺寸、重量可能是 `cm`、`kg` 等公制单位。输出给美工的图片文案和参数标注必须转换为美制单位，并保留原始值用于核对：

- 长度/尺寸：`cm × 0.3937 = in`，输出用英寸 `in`。
- 重量：`kg × 2.20462 = lb`，输出用磅 `lb`。
- 若用户同时给出公制和美制，以产品资料中的官方/包装标注为准；不确定时列入缺口清单，不得猜测。
- 图片中的主展示参数优先写美制单位；可在备注或规格说明中保留原始 `cm/kg`。
- 所有尺寸图、安装图、包装清单、A+对比表涉及尺寸/重量时，必须标明 `原始单位`、`换算后美制输出`、`换算依据`。

### Phase 1：要求用户上传主图/副图参考图

在产品资料基本完整后，必须先要求用户上传：

- 搜索结果页主图参考图
- 竞品主图
- 竞品副图
- 功能图
- 场景图
- 尺寸/安装图

这些参考图只能用于主图/副图需求稿。不得引用 A+横幅、A+模块图、A+对比表等 A+阶段参考图来设计主图或副图。

然后只输出：

- 产品定位与运营机会
- 关键词意图 / COSMO 场景意图 / Rufus 问答承接
- Review/VOC 痛点到图片模块的映射
- 主图方案
- 副图需求
- 主图/副图参考图片索引
- 文案断行方案
- 版式尺寸规范
- 主图/副图阶段验收表

主图/副图阶段图片需求正常按 7张规划，最多 9张，按产品复杂度、变体、套装、安装和场景需求拓展。需求表必须标明每张图的 `图片序位`、`数量规则`、`是否轮播`；若不是轮播，写明 `否/单张`。

**禁止在此阶段生成完整 A+需求稿。**

### Phase 2：等待用户验收主图/副图需求稿

输出主图/副图需求稿后，必须停止并等待用户确认。

用户明确回复类似以下内容后，才可以进入 A+ 阶段：

- `确认`
- `通过`
- `主图副图可以`
- `这个版本可以，继续A+`
- `验收通过`

如果用户提出修改意见，先修订主图/副图需求稿，不得直接进入 A+。

### Phase 3：要求用户上传 A+ 参考图

只有主图/副图需求稿验收通过后，才要求用户上传 A+ 参考图，包括：

- 竞品 A+ 顶部横幅
- 品牌横幅
- 功能模块图
- 场景模块图
- 对比表
- 安装/尺寸模块
- 包装/售后模块

A+需求稿只能参考用户在 A+阶段给到的 A+参考图。不得引用主图、竞品主图、竞品副图、搜索结果页截图等主图/副图阶段参考图来设计 A+模块。

A+ 参考图不足时，先要求补图，不得硬生成完整 A+。

### Phase 4：生成 A+ 需求稿

Phase 4 必须接着 Phase 1/2 已验收的 Excel 文件继续填写：

- 以主图/副图阶段已交付并经用户确认的 `.xlsx` 作为源文件。
- 保留原文件中已完成的产品资料、竞品拆解、关键词、Review/VOC、运营能力映射、主图需求、副图需求、主图/副图参考图和验收记录。
- 只在同一工作簿内继续补充 `10_A+参考图`、`11_A+需求`、A+相关合规/交付检查。
- 完成后另存为新的版本文件。
- 禁止重新复制空模板，只做一份 A+内容表。
- 禁止交付只包含 A+模块、缺少已确认主图/副图内容的 Excel。

A+ 需求稿必须包含：

- A+ 模块编号
- 模块目标
- 对应关键词意图、场景意图或 Rufus 问答
- 建议尺寸
- 画面构图
- 主标题断行版
- 副标题/正文断行版
- 文案区域和字号建议
- 参考图片直接嵌入
- 参考点/禁止照抄
- 桌面端尺寸和手机端尺寸/裁切：除 1464×600 等桌面模块尺寸外，必须考虑手机端 600×450 展示安全区
- 模块序位、数量规则、是否轮播
- 验收标准

A+需求一般按 5张/5个模块规划，按品牌故事、对比表、安装教育、包装售后等需求拓展。若 A+模块为轮播、对比表、品牌故事横幅或普通单图模块，必须在需求表中标明。

## 参考图片硬性规则

### 参考图类型隔离

必须按阶段隔离参考图来源：

- 主图/副图需求稿只能参考用户上传的主图/副图参考图。
- A+需求稿只能参考用户上传的 A+参考图。
- 主图不得参考 A+图。
- 副图不得参考 A+图。
- A+不得参考主图、竞品主图、竞品副图或搜索结果页图。
- 如果用户只提供了错误阶段的参考图，必须要求补充正确阶段参考图，不得迁就使用。

推荐编号：

```text
MAIN_REF_01：搜索结果页主图
MAIN_REF_02：竞品主图
SEC_REF_01：竞品副图/功能图
SEC_REF_02：场景图/尺寸图/安装图
APLUS_REF_01：A+顶部横幅
APLUS_REF_02：A+功能模块
APLUS_REF_03：A+场景模块/对比表
```

每张需求图必须绑定同阶段参考图编号。跨阶段编号视为不合格。

### 参考图与参考点一一对应

- `06_主图需求`、`07_副图需求` 只能从 `08_主图副图参考图` 取参考图编号、参考图片和参考点。
- `11_A+需求` 只能从 `10_A+参考图` 取参考图编号、参考图片和参考点。
- 同一需求行中的 `参考图编号`、`参考图片`、`参考点/禁止照抄` 必须来自索引表同一编号，不能把 A 图的图片配 B 图的参考点。
- 如果一张需求图引用多个编号，编号、图片、参考点必须按相同顺序逐项对应；无法确认对应关系时，先留空并要求用户补图或确认。
- 不新增 `本地路径`、`图片路径`、`附件路径` 等路径列；需求稿以嵌入图片和参考编号为准。

### 必须直接嵌入图片

Excel 需求稿中凡是出现 `参考图片` 列，必须直接贴图，不能只写：

- ASIN
- 竞品名称
- `参考B0XXXX图3`
- `见附件`
- `参考上图`

文字只能放在 `参考点/禁止照抄` 列中，用于解释：

- 参考它的什么信息层级
- 参考它的什么构图逻辑
- 哪些参数不能照抄
- 哪些文案不能照抄
- 哪些场景不能照抄

### 禁止照抄

参考图只能用于学习结构，不得复制：

- 竞品 Logo / 品牌名
- 竞品图片原图
- 竞品文案
- 竞品参数
- 竞品人物/场景
- 竞品版式和颜色组合的完整复刻

## 文案断行硬性规则

图片文案必须给「实际可放图的断行版」，而不是整段英文。

### 输出格式

```text
主标题断行版：
No Hardwiring
Needed

副标题/子项断行版：
Screw-Mounted Base
Clean Wireless Look
```

### 不合格

```text
No Hardwiring Needed Screw-Mounted Base Clean Wireless Look
```

### 分层要求

每张图必须区分：

- 主标题
- 副标题
- 子项
- 注释/参数

每一层都要标注建议字号、位置和最大行数。

## 表格样式硬性规则

所有 Excel 表格必须统一：

- 不得出现顶部异常空白深色条
- 不得出现大面积空白合并单元格
- 表头统一深色底白字
- 正文统一白底、自动换行、浅边框
- 参考图片列固定宽度
- 图片行固定行高
- 文案列开启自动换行
- 主图/副图需求表必须包含图片序位、数量规则、是否轮播
- A+需求表必须包含模块序位、数量规则、是否轮播、手机端尺寸/裁切
- 所有 Sheet 风格一致
