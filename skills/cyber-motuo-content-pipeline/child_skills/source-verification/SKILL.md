# 原始信源与事实核验

## 核验顺序
1. 官方公告、官方产品文档、论文/研究原文、监管文件。
2. 原始当事方的技术博客、演讲或公开访谈。
3. 高质量媒体的独立报道。
4. 社区帖子只作为线索，不单独支撑关键事实。

## 必核字段
- 事件发生时间、公告发布时间、AIHOT收录时间分别记录。
- 产品名称、版本、可用地区、套餐、Beta/GA状态。
- 数据分母、样本范围、统计周期和单位。
- 价格、额度、性能、延迟、参数等具体数字。
- 合作、谈判、测试、正式上线之间的状态差别。
- 原文中的限制条件、免责声明和例外情况。

## 证据规则
- 关键事实优先使用一手来源。
- 重要或争议事实尽量用两个独立来源交叉核对。
- 研究数据保留研究对象、样本量、测试时间和局限。
- “正在谈判”不能写成“已经合作”。
- Beta不能写成正式稳定版。
- 媒体报道不能改写成官方宣布。
- 定性访谈不能写成随机抽样或总体统计。
- 特定测试环境结果不能外推为平台永久规则。

## 事实标签
已确认事实 / 当事方自述 / 媒体报道 / 研究观察 / 分析推断 / 未核实或冲突。

未核实内容不进入正文，或明确写出不确定性。

## 引用与版权
- 优先链接原始来源。
- 不复制整段文章或长篇原文。
- 引用只保留必要短句。
- 对研究结论用自己的话重新组织，不直接翻译拼接摘要。
- 每个关键数据和结论附近放来源引用或链接。

## 输出
交付研究资料包：事件时间线、原始来源、核验事实表、冲突点、研究局限、可写角度、不能写的结论。
